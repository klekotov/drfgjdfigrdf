# Защита Multi Tool

## Что включено

- Release-профиль Rust с LTO, одним codegen unit, `panic = "abort"` и удалением символов.
- Отключение WebView DevTools, browser extensions и горячих клавиш масштабирования в Tauri-окне.
- Блокировка распространённых сочетаний для открытия инспектора в production-сборке.
- Определение открытых DevTools по изменению размеров WebView. После обнаружения методы `console` заменяются на no-op-заглушки.
- Production-сборка без sourcemap-файлов.
- Production JavaScript проходит минификацию и дополнительную обфускацию.
- `integrity.json` с SHA-256-хешами скомпилированных JS/CSS/assets и runtime-проверка этих файлов.
- Ограничение ярлыка и окна не влияет на разработку: защитные проверки выключены в Vite dev-режиме.

## Ограничения

Нельзя сделать desktop-приложение полностью неразбираемым: пользователь контролирует компьютер, на котором выполняется код. Frontend-код всё равно можно анализировать, а native-код — дизассемблировать.

Текущий `integrity.json` защищает от случайной или частичной подмены файлов. Для защиты от атакующего, который может заменить весь каталог приложения, нужен подписанный манифест и подпись самого Windows Setup.

Приложение не скрывает, не блокирует и не завершает системные инструменты. От доступа к секретам это не защищает — секретные операции должны выполняться на сервере, а клиент не должен содержать ключи.

## Релиз

Для доверенного распространения Windows-версии дополнительно используйте Authenticode-сертификат организации для подписи `.exe` и установщика. Сертификат и закрытый ключ нельзя хранить в репозитории или в собранном приложении — их следует передавать только через защищённое хранилище CI.
